# Proposal for Dynamic, Context-Dependent Node IDs

## Problem Overview
Currently, the system relies on a strict, static hashing mechanism (`crate::lcs::stable_node_id`) to map string predicates (like `"run"`) to a deterministic 64-bit `NodeId` using the FNV-1a hash. This ensures cross-language compatibility during IPC between Python and Rust.

However, a static hash means that the word `"run"` always maps to the same `NodeId`, regardless of its syntactic context, modal mode, or the active environment (`Env`). This restricts the ability to maintain dynamic, situationally-dependent semantics where a predicate might mean different things or carry different weights depending on the grammatical or reasoning context (e.g., `"run"` as a noun vs. a verb, or `"run"` in a hypothetical vs. a factual context).

During the cleanup of unused code warnings, an unused wrapper function `stable_node_id` in `core/src/generation/vocab_distribution.rs` was removed. It was merely a pass-through to the static FNV-1a hash and did not provide any contextual capabilities.

## Proposed Solution: Contextual Node Hashing

To achieve dynamic node values dependent on context, we must upgrade the hashing mechanism to incorporate context variables—such as the active environment (`Env`), modal mode (`ModalMode`), or type category (`TypeCategory`)—directly into the identity of the node.

### 1. Introduce a `contextual_node_id` Function
Instead of relying solely on the predicate string, we can define a new hashing function that combines the predicate with relevant contextual metadata.

```rust
pub fn contextual_node_id(predicate: &str, env: Env, mode: ModalMode) -> u64 {
    // Combine the predicate and context into a single byte stream
    let mut combined = String::with_capacity(predicate.len() + 16);
    combined.push_str(predicate);
    combined.push('_');
    combined.push_str(&env.to_string());
    combined.push('_');
    combined.push_str(&mode_to_u8(mode).to_string());

    // Hash the combined string using the existing FNV-1a implementation
    crate::lcs::fnv1a_64_bytes(combined.as_bytes())
}
```

### 2. Update the `lcs::converter`
The core `converter` component currently uses `stable_node_id` to assign IDs when building `ArgNode`s from tokens. This process must be updated to inject context when assigning the `NodeId`.

*   **Change:** Modify the `stable_node_id_from_structure` or equivalent functions to accept and hash context parameters.
*   **Why:** This ensures that the generated nodes immediately reflect their context at the boundary between Python and Rust.

### 3. IPC Compatibility (Python Parity)
Since the `NodeId` identity is critical for IPC compatibility, the Python component must exactly mirror this contextual hashing function.

*   **Change:** Update the Python `mtlg` node construction logic to hash the predicate combined with its environment/mode exactly as defined in Rust.
*   **Why:** Without strict parity, the Python and Rust components will disagree on node identities, breaking the teacher forcing signals and inference tracking.

### 4. Updating `VocabDistribution` and Cross-Entropy Signals
The `VocabDistribution` currently scores probabilities over static `NodeId`s. With contextual hashing, the distribution will naturally distinguish between contextual variants of the same word.

*   **Change:** The teacher forcing signals generated by `ce_quality_split` will automatically push quality updates to the specific contextual variant (e.g., `run_hypothetical` vs. `run_factual`) rather than applying a blanket update to the generic `"run"` node.
*   **Why:** This fulfills the goal of dynamic node values, allowing the learning algorithm (via `CausalTransitionRegistry` and `PerfRegistry`) to assign different attribution scores to a word based on its context.

## Summary of Changes Made in the Cleanup Patch

To prepare for this future architecture, the cleanup patch performed the following related actions:

1.  **Removed Unused Static Hash Wrapper:** The `stable_node_id` wrapper in `vocab_distribution.rs` was removed because it was unused and merely delegated to the static hash. It provided no contextual benefit and would only clutter the namespace when introducing the new `contextual_node_id`.
2.  **Integrated Causal Type Consistency:** The unused `estimate_type_consistency` and `type_consistency_score` functions were integrated directly into the `compute_causal_delta` math. This is a critical step because it ensures that attribution scores are now weighted by type consistency—a foundational requirement for context-dependent reasoning, as it heavily penalizes contexts where a node's expected modal mode contradicts its structural application.
3.  **Removed Dead Imports and Variables:** Leftover imports (e.g., `TypeCategory`, `EdgeRef`) and unused variable warnings were cleaned up to ensure a clean slate for the upcoming contextual architecture.
